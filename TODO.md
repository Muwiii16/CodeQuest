## Class tests, Kahoot style (done)
- Scoring (Class Test Mode only): a correct answer is worth 500-1000 points depending on how much of the question's time was
  left, plus a streak bonus (+100 per extra correct in a row, max +500). Wrong or too slow = 0 and the streak resets.
  Nobody loses health and there are no hints, so everyone plays every question. Campaign scoring is unchanged.
- While playing: live "Rank #n of m", points behind the next player, and the streak, in the sidebar and after each answer.
- After finishing: a "You finished!" card with points and place while others catch up, then the podium reveal
  (3rd, 2nd, 1st) and the full ranking once everyone is done or the professor ends the test. No rewards, no grade percentage.
- The professor sees live points per student, then the podium and ranking when the test ends.
- Resume: every answer is saved to `~/CodeQuest/cache/classtest-<session>-<user>.json` (and the running score is uploaded).
  Reopening Class Test while the test is still running shows "Resume test", which replays the answers (the questions are
  seeded per session, so it lands on the same question). The save is deleted when the test is finished or over.
- Not done: resume for campaign lessons (their questions are random, so a replay would not match); a professor cannot reopen
  the podium of an ended test later (the lesson Analysis table still shows each student's best class-test points).

## Round 10: lessons that build one program (Nov 2026)
Migration `lwjgl3/src/supabase/migrations/20261118120000_lesson_program.sql` (applied): `stages.program` (the full C program) and `challenges.code_chunk` (the lines a question adds). Additive; lessons without a program are unchanged.
- **Idea:** a lesson has one full program. Its questions, in order, are chunks of it; each answered question adds its chunk to the code block on the right (green if right, red if wrong, the correct lines either way, so the whole program is built up). The block is auto-indented by brace depth (`CodeBlock.lines()`).
- **Chunks:** multiple choice, fill in the blank and arrange work theirs out from the question (`CodeChunks`: the prompt with the blank filled; arranged tokens written like code). True/false and find-the-bug questions need the lines written in the editor.
- **Play:** `ProgramChallengeProvider` serves the questions in program order, one tower each (max 10, `MAX_SLOTS`), sections built from them. A lesson with a program whose questions all have chunks plays this way; a lesson with no questions plays a built-in program for its map (`BuiltInPrograms`: 3 programs, the third is the calculator); any other lesson keeps the old random mode with kind rotation. Class tests work the same, with no randomness.
- **Professor:** new `ProfessorProgramScreen` (write the program, "Check against the questions" shows which lines are covered and the first mismatch, "Use the built-in program"); the lesson screen shows the coverage and has Edit/Write the program; the question editor asks for the chunk of true/false and find-the-bug questions.
- Tested (`ProgramLessonTest`) and checked on screen: a built-in program lesson played to the end with right and wrong answers, the program screen and the chunk box.
- Open: one question per chunk, so adaptive difficulty only changes the time per question in program lessons (difficulty variants of one chunk are not supported yet). No reorder button: order is creation order. Wrong-answer code in red shows the correct lines. AI-written programs and chunks are part of the later Gemini step. The ERD needs `stages.program` and `challenges.code_chunk`.
